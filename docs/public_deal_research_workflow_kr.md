# 공개자료 기반 실제 딜 모델링 워크플로우

이 프로젝트는 실제 IM이나 내부 렌트롤을 갖고 있지 않은 취업준비 상황을 전제로 한다. 따라서 실제 공개 딜을 모델링할 때는 "확인된 사실"과 "분석을 위한 추정"을 분리해야 한다.

## 1. 왜 Source Tracker가 필요한가

공개 웹자료만으로는 부동산 딜의 모든 입력값을 알기 어렵다. 예를 들어 매입가는 기사나 공시에서 확인될 수 있지만, 정확한 임대면적, 임차인별 임대료, 운영비, CAPEX, 대출 금리 조건은 공개되지 않는 경우가 많다.

그래서 이 프로젝트는 각 입력값을 다음 기준으로 관리한다.

```text
Field: 어떤 입력값인지
Value: 모델에 넣은 값
Source Type: 공시 / 마켓 리포트 / 기사 / 직접추정
Evidence Status: 확인값 / 공개자료 참고값 / 모델링 추정치 / 추가 확인 필요
Confidence: High / Medium / Low
Source URL: 근거 자료 링크
Note: 왜 이 값을 썼는지, 무엇을 추가 확인해야 하는지
```

이 구조가 있어야 면접에서 "그 숫자는 어디서 왔나요?"라는 질문에 답할 수 있다.

## 1.1 확인가능한 값과 추정치 구분

앱의 `Source Tracker`는 각 입력값을 네 가지로 나눈다.

```text
Confirmed
- 공시나 보고서에서 숫자 자체를 직접 확인한 값
- 예: 공시상 매입가, 차입금, 임대수익, 감정평가액

Public reference
- 숫자 자체는 모델 입력값과 1:1로 같지 않지만, 공개자료가 방향성을 뒷받침하는 값
- 예: 권역별 공실률, 시장 임대료, Cap Rate 범위, 거래시장 분위기

Modeled estimate
- 공개자료만으로 정확히 알 수 없어 모델링 목적상 둔 추정치
- 예: 운영비, CAPEX, 경제적 공실률, 보유기간, Exit 비용

To verify
- 공개자료에서 확인해야 하지만 아직 모델에 임시로 넣어둔 값
- 예: 기사에서 본 매입가를 공시 원문으로 아직 대조하지 못한 경우
```

면접에서는 `Confirmed`와 `Modeled estimate`를 섞어서 말하면 안 된다. 오히려 “공개자료로 확인 가능한 값과 추정치를 의도적으로 분리했다”고 설명하는 것이 강하다.

## 2. 예시 딜: SK Seorin Building Public Research Case

앱에는 `SK Seorin Building public research case`를 예시로 넣었다. 이 케이스는 특정 회사의 내부 모델을 복제한 것이 아니라, 공개자료 리서치 방식으로 안정화 오피스 딜을 모델링하는 예시다.

사용한 공개자료 경로:

```text
DART 전자공시시스템
https://dart.fss.or.kr/

국토교통부 리츠정보시스템
https://reits.molit.go.kr/

JLL Korea Market Dynamics
https://www.jll.com/ko-kr/insights/market-dynamics
```

현재 앱에 입력된 값 중 일부는 공개자료에서 바로 확인해야 할 항목이고, 일부는 모델링을 위한 추정값이다. 이 구분이 핵심이다.

## 3. 직접 리서치할 때의 순서

### 3.1 딜/자산 식별

먼저 자산명, 매수자, 매도자, 거래 시점, 자산 유형을 확인한다.

```text
예: SK Seorin Building
자산 유형: 서울 CBD 오피스
투자 성격: 안정화 오피스 / 장기 임차인 기반
```

### 3.2 DART에서 확인할 항목

DART에서는 다음을 찾아본다.

```text
증권신고서
투자설명서
사업보고서
반기/분기보고서
자산 취득 관련 공시
차입 관련 주석
임대수익 또는 영업수익 관련 주석
```

확인하면 좋은 값:

```text
매입가
감정평가액
차입금
담보 설정
임대수익
이자비용
자산별 장부가
```

### 3.3 리츠정보시스템에서 확인할 항목

리츠정보시스템에서는 리츠의 자산 현황과 투자보고서를 확인한다.

확인하면 좋은 값:

```text
투자대상 자산
소재지
자산 규모
임대 현황
운용 현황
배당 관련 정보
```

### 3.4 마켓 리포트에서 보완할 항목

CBRE, JLL, Savills, Colliers, Cushman & Wakefield 리포트는 개별 딜의 세부 수치보다 시장 가정을 보완하는 데 유용하다.

보완할 수 있는 값:

```text
권역별 공실률
권역별 임대료 수준
Cap Rate 방향성
투자시장 거래 분위기
임대차 수요
```

## 4. 앱에서 사용하는 방법

앱 사이드바에서 다음을 선택한다.

```text
Load Deal Case
→ SK Seorin Building public research case
```

그러면 다음 값들이 자동 입력된다.

```text
매입가
임대면적
임대율/공실률
임대료
운영비
LTV
금리
Exit Cap
보유기간
```

이후 `Source Tracker` 탭에서 각 값의 출처 유형과 신뢰도를 확인한다. 신뢰도가 Medium 또는 Low인 항목은 네가 DART/리츠/리포트에서 더 정확한 값을 찾으면 직접 바꿔 넣으면 된다.

`Asset Profile` 탭에서는 투자검토 메모에 들어갈 자산/입지 정보를 따로 관리한다.

```text
자산명
주소
권역 / 하위시장
도로 / 대중교통 접근성
임차인 또는 그룹 사용 맥락
시장자료 확인 경로
```

이 정보는 숫자 모델과 별도로 중요하다. 회계법인 부동산본부의 자문 문서는 단순히 IRR만 보여주는 것이 아니라, 해당 자산이 어떤 입지에 있고 어떤 수요 논리로 현금흐름을 방어할 수 있는지 설명해야 하기 때문이다.

### 4.1 Memo에 들어가야 하는 비재무 정보

투자검토 메모에는 최소한 다음 항목이 필요하다.

```text
자산명 및 주소
권역: CBD / GBD / YBD 등
접근성: 주요 도로, 지하철역, 업무지구 연결성
입지 논리: 오피스 수요, 주변 업무시설, 임차수요 기반
임차인/사용자 맥락: 앵커 테넌트, 그룹사 사용, 장기 임대 가능성
출처 링크: 공시, 리츠정보, 시장 리포트, 기사
확인 여부: 확인값인지 추정치인지
```

앱의 `Memo` 탭은 `Asset Profile`과 `Source Tracker`를 결합해 이 정보를 자동으로 포함한다.

## 5. 면접에서 설명하는 방식

이 기능은 다음처럼 설명하면 좋다.

```text
공개자료만으로는 실제 딜의 모든 가정을 확인하기 어렵기 때문에, 확인 가능한 공시 기반 값과 모델링을 위한 추정값을 분리해 관리했습니다. 각 입력값에는 출처 유형, URL, 신뢰도, 추가 확인사항을 붙였고, 이 값들이 NOI, DSCR, IRR, Exit Value에 어떻게 연결되는지 확인할 수 있도록 했습니다. 회계법인 부동산 자문 업무에서 중요한 것은 단순 계산보다 가정의 출처와 타당성을 설명하는 것이라고 판단했습니다.
```

## 6. 자기소개서와 면접에서 활용하는 방법

자기소개서에는 프로젝트의 산출물보다 문제의식을 먼저 써야 한다.

```text
부동산 자문 업무에서는 단순히 IRR을 계산하는 것보다, 각 가정이 어떤 자료에서 왔고 어느 정도 신뢰할 수 있는지 설명하는 역량이 중요하다고 판단했습니다. 이에 공개 공시와 시장자료를 기반으로 확인 가능한 값과 모델링 추정치를 분리하고, 각 입력값의 출처·신뢰도·추가 확인사항을 관리하는 Underwriting Copilot을 구축했습니다.
```

SRT-RE 부동산본부 지원용으로는 다음 문장이 더 직접적이다.

```text
부동산 거래 자문에서는 수익률 계산뿐 아니라 자산의 위치, 권역, 임차수요, 출처가 확인된 가정과 추정 가정을 구분해 클라이언트에게 설명하는 역량이 중요하다고 보았습니다. 이에 공개자료 기반 딜 사례에 대해 자산 프로필, 입지 논리, 가정 출처, 신뢰도, 민감도 분석을 하나의 투자검토 메모와 Excel 모델로 연결하는 도구를 구현했습니다.
```

면접에서는 다음 순서로 설명하면 좋다.

```text
1. 실제 IM이나 내부 렌트롤은 비공개라서 접근이 어렵다.
2. 그래서 공개자료 기반 리서치 케이스로 접근했다.
3. 확인된 값과 추정치를 Source Tracker로 분리했다.
4. 추정치는 민감도 분석으로 결과 영향도를 확인했다.
5. 최종적으로 NOI, DSCR, IRR, Exit Value가 어떤 가정에 민감한지 설명할 수 있게 만들었다.
```

질문이 들어오면 이렇게 답하면 된다.

```text
Q. 이 숫자들은 실제 값인가요?
A. 전부 실제 값이라고 말하지 않았습니다. 공시나 공개자료로 확인 가능한 값, 시장자료로 보완한 참고값, 모델링을 위한 추정치를 분리했습니다. 이 프로젝트의 목적은 특정 딜을 완벽히 복제하는 것이 아니라, 제한된 공개자료에서 가정을 구조화하고 검증 가능한 재무모델로 연결하는 과정을 보여주는 것입니다.
```

```text
Q. 추정치가 많으면 모델의 의미가 약하지 않나요?
A. 그래서 추정치를 숨기지 않고 별도로 표시했습니다. 부동산 자문 실무에서도 초기 검토 단계에서는 모든 자료가 완비되지 않는 경우가 많기 때문에, 어떤 가정이 확인값이고 어떤 가정이 민감도 검토 대상인지 구분하는 것이 중요하다고 봤습니다.
```
