# Office Deal Underwriting Copilot 설명서

이 프로젝트는 실제 매각 티저나 IM을 확보하지 못한 취업준비 상황을 전제로 한다. 따라서 특정 실거래 딜을 복제하기보다, 실무에서 사용하는 오피스 매입 검토 구조를 가상의 딜에 적용해 재무모델링 역량을 보여주는 방식으로 설계한다.

## 1. 가상 딜은 어떻게 짜야 하는가

가상 딜은 아무 숫자나 조합하는 것이 아니라, 하나의 투자 스토리를 먼저 정하고 그 스토리에 맞는 가정을 넣어야 한다.

### 1.1 딜 컨셉 먼저 정하기

예시:

```text
딜명: Yeouido Office Acquisition
자산 유형: 안정화된 프라임/준프라임 오피스
위치: 여의도권역
투자 전략: 안정적 임대수입 + 5년 후 매각
보유기간: 5년
자본구조: Senior Loan 60%, Equity 40% 내외
핵심 리스크: 금리, Exit Cap, 임대료 성장률, 매각가 의존도
```

이렇게 컨셉을 먼저 잡으면 숫자의 방향이 자연스럽게 정해진다. 예를 들어 안정화 오피스라면 공실률은 너무 높지 않아야 하고, 개발형 사업처럼 CAPEX가 크거나 임대수입이 0에서 시작하면 안 된다.

### 1.2 매입가를 정하는 방식

오피스 매입가는 대략 다음 논리로 잡는다.

```text
매입가 = Year 1 NOI / Entry Cap Rate
```

예를 들어 Year 1 NOI가 50억원이고 Entry Cap Rate를 5.0%로 보면:

```text
50억원 / 5.0% = 1,000억원
```

이 프로젝트의 기본 가정도 비슷한 구조다.

```text
임대면적: 30,000 sqm
연 임대료: 280,000원/sqm
공실률: 8%
운영비: 70,000원/sqm
매입가: 1,000억원
```

이 조합은 Year 1 NOI가 약 50억원 수준이고, Entry Cap Rate가 약 5%가 되도록 맞춘 것이다.

### 1.3 임대수입 가정 잡기

임대수입은 다음 구조로 계산한다.

```text
Potential Gross Income = 임대면적 x 연 임대료
Vacancy Loss = Potential Gross Income x 공실률
Effective Gross Income = Potential Gross Income - Vacancy Loss
NOI = Effective Gross Income - 운영비
```

가상 딜에서는 임대료를 시장 실제 숫자로 정확히 맞추기보다, 계산 결과가 상식적인 Entry Cap Rate와 DSCR을 만들도록 조정하는 것이 중요하다.

### 1.4 대출 가정 잡기

취업 포트폴리오용 안정화 오피스 딜에서는 단순하게 시작하는 것이 좋다.

```text
LTV: 55~65%
금리: 4~6%
상환방식: Interest-only
대출수수료: 1%
```

처음부터 Tranche, 메자닌, 우선주, 배당 waterfall까지 넣으면 설명 난이도가 크게 올라간다. V1에서는 Senior Loan 하나만 두는 것이 낫다.

### 1.5 Exit Cap 가정 잡기

Exit Cap은 매각가를 결정하는 핵심 변수다.

```text
Exit Value = 매각 다음 연도 NOI / Exit Cap Rate
```

예를 들어 다음 연도 NOI가 55억원이고 Exit Cap이 4.8%라면:

```text
55억원 / 4.8% = 약 1,146억원
```

Exit Cap이 낮을수록 매각가가 올라가고 IRR도 좋아진다. 그래서 이 프로젝트에서는 Exit Cap 민감도 분석과 매각가 의존도 점검을 중요하게 둔다.

### 1.6 좋은 가상 딜의 기준

좋은 가상 딜은 다음 조건을 만족한다.

```text
Entry Cap이 상식적인 범위에 있다.
Levered IRR이 너무 과장되지 않는다.
DSCR이 1.2x 이상으로 유지된다.
수익률이 전부 매각차익에만 의존하지 않는다.
민감도에서 하방 시나리오가 의미 있게 드러난다.
```

즉, “좋은 결과가 나오는 딜”보다 “리스크와 수익성이 함께 보이는 딜”이 더 좋은 포트폴리오 소재다.

## 2. 이 코파일럿의 전체 흐름

이 도구의 핵심 흐름은 다음과 같다.

```text
입력 가정
→ 운영현금흐름 계산
→ 대출 스케줄 계산
→ 매각가치 계산
→ 자기자본 현금흐름 계산
→ 수익률 지표 산출
→ 민감도/역산/리스크 점검
→ Excel 모델 및 투자검토 메모 생성
```

중요한 점은 AI가 숫자를 계산하지 않는다는 것이다. 숫자는 Python 계산 엔진이 처리하고, AI는 향후 자연어 입력 정리와 메모 작성 보조에만 쓰는 구조다.

## 3. 기능별 상세 설명

### 3.1 Deal Assumptions 입력

앱의 사이드바에서 다음 가정들을 입력한다.

```text
매입가
임대면적
임대율
연 임대료
운영비
임대료 성장률
공실률
CAPEX
LTV
금리
Exit Cap Rate
보유기간
목표 IRR
```

이 입력값은 실무상 IM, 렌트롤, 시장자료, 금융조건, 매각가정에서 가져오는 항목들이다. 현재는 사용자가 직접 입력하지만, 향후 AI가 자연어 딜 설명을 이 구조로 변환하도록 확장할 수 있다.

### 3.2 Operating Cash Flow

운영현금흐름 탭은 자산이 매년 만들어내는 현금흐름을 보여준다.

주요 항목:

```text
Potential Gross Income: 만실 기준 임대수입
Vacancy Loss: 공실로 인한 손실
Effective Gross Income: 실제 임대수입
Operating Expense: 운영비
NOI: 순영업소득
CAPEX: 수선비/자본적 지출
Asset Management Fee: 운용보수
Cash Flow Before Debt: 대출상환 전 현금흐름
```

면접에서 설명할 때는 “NOI는 부동산 자체의 운영성과를 보는 지표이고, 대출조건과 무관하게 자산의 수익력을 보여준다”고 말하면 된다.

### 3.3 Debt Schedule

Debt 탭은 대출 구조와 부채상환능력을 보여준다.

주요 항목:

```text
Beginning Debt: 기초 대출잔액
Interest: 이자비용
Principal: 원금상환
Debt Service: 원리금상환액
Ending Debt: 기말 대출잔액
DSCR: NOI / Debt Service
ICR: NOI / Interest
Debt Yield: NOI / 대출잔액
```

현재 V1은 Interest-only 구조를 기본으로 한다. 즉 보유기간 중 원금은 상환하지 않고, 매각 시 대출잔액을 상환한다.

### 3.4 Returns

Returns는 투자자 관점의 현금흐름과 수익률을 계산한다.

주요 지표:

```text
Levered IRR: 대출을 반영한 자기자본 IRR
Unlevered IRR: 대출 없이 자산 자체 기준 IRR
Equity Multiple: 회수한 총 자기자본 / 투입 자기자본
Cash-on-Cash Yield: 연간 배당성 현금흐름 / 투입 자기자본
NPV: 할인율 기준 순현재가치
```

Levered IRR이 Unlevered IRR보다 높다면 대출이 수익률을 높이는 효과가 있다는 뜻이다. 다만 금리 상승이나 NOI 하락 시 레버리지 리스크도 함께 커진다.

### 3.5 Exit Value

매각가치는 다음 방식으로 계산한다.

```text
Exit Value = 매각 다음 연도 NOI / Exit Cap Rate
```

매각연도 NOI가 아니라 다음 연도 NOI를 쓰는 이유는, 매수자가 매입 후 받을 안정화 수익을 기준으로 가격을 산정한다고 보기 때문이다.

### 3.6 Sensitivity

Sensitivity 탭은 Exit Cap과 임대료 성장률을 바꿨을 때 Levered IRR이 어떻게 변하는지 보여준다.

예시 구조:

```text
가로축: Exit Cap 4.4% / 4.6% / 4.8% / 5.0% / 5.2%
세로축: Rent Growth 0% / 1% / 2% / 3% / 4%
결과값: Levered IRR
```

이 기능은 “기준 시나리오 하나만 보는 것이 아니라, 핵심 변수 변화에 따른 하방 리스크를 검토했다”는 점을 보여준다.

### 3.7 Reverse Underwriting

목표 IRR을 입력하면 그 IRR을 만족하는 최대 매입가를 역산한다.

예를 들어 기준 가정에서 목표 IRR을 10%로 두면, 현재 모델은 최대 매입가를 약 940억원 수준으로 계산한다.

이 기능은 실무적으로 매우 중요하다. 단순히 “이 가격이면 수익률이 얼마인가?”가 아니라, “목표 수익률을 맞추려면 얼마까지 써도 되는가?”를 보여주기 때문이다.

### 3.8 Risk Checks

Checks 탭은 계산 결과를 기반으로 이상값이나 위험한 가정을 자동 탐지한다.

현재 점검 항목:

```text
DSCR 1.20x 미만 여부
LTV 과다 여부
공실률이 너무 낮은지
임대료 성장률이 과도한지
Exit Cap이 Entry Cap보다 지나치게 낮은지
수익이 매각차익에 과도하게 의존하는지
Sources와 Uses가 일치하는지
Debt Yield가 낮은지
```

이 기능은 포트폴리오에서 특히 강하다. 단순 계산기가 아니라, 주니어 애널리스트가 놓칠 수 있는 오류를 점검하는 도구처럼 보이기 때문이다.

### 3.9 Excel Export

Excel 다운로드 기능은 계산 결과를 8개 시트로 내보낸다.

```text
01_Cover
02_Assumptions
03_Sources_Uses
04_Operating_CF
05_Debt
06_Returns
07_Sensitivity
08_Checks
```

Excel에는 Python 계산 결과뿐 아니라 IRR과 Equity Multiple 검산용 Excel 수식도 포함되어 있다. 이 구조는 “화면 계산값과 Excel 모델이 같은 논리를 따른다”는 점을 보여준다.

### 3.10 Memo

Memo 탭은 계산 결과를 바탕으로 한국어 투자검토 메모 초안을 생성한다.

구성:

```text
투자 개요
주요 수익성 지표
자본구조 및 부채상환능력
매각가정
주요 위험요인 및 추가 확인사항
```

현재는 규칙 기반 문장 생성이다. 향후 OpenAI API를 붙이면 이 부분을 LLM이 더 자연스럽게 작성하도록 확장할 수 있다. 단, 계산값 자체는 계속 Python 엔진에서 가져와야 한다.

## 4. 면접에서 설명하는 방식

이 프로젝트는 다음처럼 설명하면 좋다.

```text
실제 딜 자료를 확보하기 어려운 상황이어서, 안정화 오피스 매입 딜을 가정해 재무모델링 구조를 직접 구현했습니다. 핵심 계산은 LLM에 맡기지 않고 Python 엔진으로 고정했으며, NOI, Exit Value, Debt Schedule, Levered IRR, DSCR, 민감도, 목표수익률 기준 매입가 역산을 계산하도록 설계했습니다. AI는 향후 자연어 입력을 구조화하거나 투자검토 메모 초안을 작성하는 보조 기능으로 제한해, 계산의 검증 가능성을 유지하는 방향으로 설계했습니다.
```

좋은 답변의 핵심은 다음이다.

```text
AI가 재무모델을 만들어줬다
```

가 아니라,

```text
재무모델의 계산 구조는 직접 설계했고, AI는 반복적인 입력 정리와 검토 메모 작성을 보조하게 했다
```

라고 말하는 것이다.

## 5. 다음 고도화 방향

포트폴리오 완성도를 높이려면 다음 순서가 좋다.

```text
1. 렌트롤 업로드 기능
2. WALE, 임차인 집중도, 만기 집중도 분석
3. 목표 DSCR 기준 최대 금리 역산
4. 자연어 딜 설명을 구조화된 가정값으로 변환
5. 투자검토 메모 PDF/Word 출력
6. 화면 계산값과 Excel 수식값 비교 검증
```

이 중 가장 먼저 추가할 기능은 렌트롤 분석이다. 부동산 자문 직무와 가장 직접적으로 연결되고, “가상의 단순 딜”에서 “실제 자료를 업로드해 분석하는 도구”로 발전하기 때문이다.
